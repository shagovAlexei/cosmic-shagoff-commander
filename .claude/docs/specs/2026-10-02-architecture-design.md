# Shagoff Commander: архитектура и процесс

Дата: 2026-10-02. Статус: одобрен.

## Цель

Двухпанельный файловый менеджер для Pop!_OS 24.04 (COSMIC), написан на Rust и libcosmic. Внешний вид и клавиатура как можно ближе к Total Commander для Windows. Человек, который годами работал в TC, должен работать здесь «на автомате»: Tab, F5, Insert, Num+ делают то же, что в TC.

Готовность MVP: им можно пользоваться каждый день вместо cosmic-files для обычной работы с локальными файлами.

## Решения

| Вопрос | Решение |
|---|---|
| Лицензия | GPL-3.0-only. Можно брать код из cosmic-files (у него тоже GPL-3.0-only) |
| Имена | репозиторий `shagovAlexei/cosmic-shagoff-commander`, бинарник `shagoff-commander`, APP_ID `io.github.shagovAlexei.cosmic-shagoff-commander`, в меню «Shagoff Commander» |
| Основа | своё приложение на libcosmic. cosmic-files не подключаем зависимостью и не форкаем, только копируем отдельные модули |
| libcosmic | закреплён по `rev` в `crates/app/Cargo.toml` и обновляется отдельным PR |
| Объём MVP | ядро TC и вкладки в каждой панели |

### Почему не cosmic-files как библиотека и не форк

- Выделение в cosmic-files сделано флагом `Item.selected`. Отдельного курсора нет, а в TC курсор и отметки Insert — разные вещи. Поля приватные, поменять их снаружи нельзя.
- `operation::Operation::perform` сразу шлёт `app::Message` cosmic-files, поэтому без их `App` модуль не работает. `mounter` приватный.
- При подключении зависимостью наша ревизия libcosmic обязана совпадать с их ревизией, а их API меняется без предупреждения.
- Форк означает файлы по 7–8 тыс. строк (`tab.rs`, `app.rs`) и конфликты при каждом обновлении из апстрима.

### Что копируем из cosmic-files

Каждый файл копируется в PR той вехи, где он впервые нужен, и с пометкой источника в начале файла:

- `src/operation/controller.rs`: пауза, отмена и прогресс операции.
- `src/operation/recursive.rs`: рекурсивное копирование и перемещение. Сначала пробует rename, при неудаче копирует и удаляет. Колбэки `on_progress` и `on_replace`.
- Позже, по необходимости: `mounter/gvfs.rs`, `mime_icon.rs`, `clipboard.rs`.

Скопированный код отвязываем от `app::Message`: прогресс и вопросы о конфликтах идут через канал, который передаёт вызывающий код.

## Архитектура

Cargo workspace из двух крейтов.

### `crates/core` — `shagoff-core`

Не зависит от libcosmic. Вся логика здесь, и вся она покрыта unit-тестами.

- `panel.rs` — `Panel { cwd, entries, cursor, marked, sort, show_hidden }`. Только чистые функции:
  - `move_cursor(delta)` и `cursor_to(Home | End)`
  - `toggle_mark()`: Insert отмечает строку и сдвигает курсор вниз. Space просто отмечает.
  - `mark_by_mask(glob, on)` для Num+ и Num−, `invert()` для Num*, `mark_all(on)`
  - `set_sort(column)`: повторный выбор той же колонки меняет направление
  - `targets()`: если есть отметки, возвращает отмеченные файлы, иначе файл под курсором. На этом правиле TC строятся все операции.
  - Строка `..` не отмечается никогда.
- `listing.rs` — `scan(path, show_hidden) -> io::Result<Vec<Entry>>` на `std::fs`. Строка `..` идёт первой, затем папки, затем файлы, в каждой группе своя сортировка. `Entry { name, ext, size, mtime, kind (Dir | File | Symlink), perms }`.
- `ops/` — `enum Operation { Copy, Move, Mkdir, Trash, Delete, Rename }`. В корзину удаляем через крейт `trash`. Код по образцу cosmic-files: `controller.rs`, `recursive.rs`. Операции асинхронные (tokio), в UI отдают события `Progress`, `Conflict(reply_tx)`, `Done` и `Error`.

### `crates/app` — `shagoff-commander`

Интерфейс на libcosmic.

- `app.rs` — `App { panes: [Pane; 2], active: Side, ops }`. Сообщения вида `Message::Pane(Side, PaneMsg)` и `Message::Op(..)`. Ветки `update()` тонкие: вызывают функцию ядра или запускают задачу.
- `pane.rs` — `Pane { tabs: Vec<Tab>, active_tab }`, где `Tab = core::Panel + scroll`.
- `view/` — раскладка окна TC сверху вниз:
  1. кнопки дисков у каждой панели;
  2. вкладки;
  3. строка текущего пути;
  4. заголовки колонок (клик сортирует);
  5. таблица файлов: Имя, Расш., Размер, Дата, Атрибуты;
  6. строка состояния («0 Б из 1,2 МБ, файлов 0 из 15»);
  7. кнопки F3–F8 внизу окна.

  Активная панель видна по заголовку пути. Курсор — рамка или подсветка строки. Отмеченные строки выделены цветом текста, как в TC.
- `keymap.rs` — одна таблица `KeyBind → Action`, раскладка по умолчанию повторяет TC (см. `.claude/docs/tc-reference.md`). Клавиши и кнопки F-панели приводят к одному и тому же `Action`.
- `dialogs.rs` — модальные окна через `Application::dialog()`:
  - копирование и перенос: поле «куда» заполнено путём другой панели, его можно править;
  - новая папка;
  - подтверждение удаления;
  - конфликт: «Заменить / Пропустить / Заменить все / Пропустить все / Отмена».
- `watcher.rs` — `notify` следит за cwd обеих панелей и при изменении перечитывает каталог.
- `config.rs` — cosmic-config `#[version = 1]`: последние пути и вкладки, `show_hidden`, внешний просмотрщик и редактор. У каждого поля есть `Default`.

### Поток данных

```
клавиша / кнопка F → keymap → Action → App::update
   ├─ навигация, выделение → функция core::Panel (синхронно, чистая)
   ├─ смена каталога      → Task: spawn_blocking(listing::scan) → Message::Listed
   └─ файловая операция   → диалог → Task: ops::run → поток событий
                              Progress / Conflict(диалог, ответ в канал) / Done / Error
                              → по Done перечитать обе панели
```

### Ошибки

- Нет прав на чтение каталога: остаёмся в прежнем каталоге и показываем сообщение в строке состояния. Панель при этом не очищается.
- Ошибка посреди операции: показываем диалог «Повторить / Пропустить / Отмена». Уже сделанная часть не откатывается, как и в TC.
- Без корзины удаляем только по Shift+F8 и всегда после подтверждения.

### Тестирование

- Ядро: unit-тесты на всю логику `Panel` и на `listing`/`ops` во временных каталогах (`tempfile`).
- UI: ручная проверка по чек-листу в `TESTING.md`. Каждый исправленный баг получает именованный регрессионный тест в ядре.
- `just verify` = `cargo fmt --check` + `clippy -D warnings` + `cargo test`, его же запускает CI.

## Упрощения MVP

Каждое из них потом станет отдельной фичей со своим брейнштормом.

- F3 и F4 запускают внешние программы (по умолчанию `xdg-open` и `cosmic-edit`, меняется в конфиге). Своего Lister пока нет.
- Список дисков берём из `/proc/self/mounts` (только реальные ФС) и добавляем к нему «Домой» и `/`. gvfs, сеть и монтирование не поддерживаем.
- Вид только «Подробно». Режимов Brief и эскизов нет.
- Без иконок по MIME: только значки «папка» и «файл».

## Процесс

1. Брейншторм (`superpowers:brainstorming`) → спек `.claude/docs/specs/YYYY-MM-DD-<тема>.md`.
2. План (`superpowers:writing-plans`) → `.claude/docs/plans/NN-<тема>.md`.
3. Ветка `feat/<тема>`. Логику ядра пишем через TDD. Перед PR — `just verify`.
4. `/code-review` → PR через `gh` → зелёный CI → merge в `main`. Напрямую в `main` не коммитим.

## Вехи MVP

Одна веха — один PR.

0. **Bootstrap**: репозиторий, workspace, justfile, CI, документация, пустое окно.
1. **core**: `Panel`, `listing`, сортировка, тесты.
2. **Две панели**: таблица, курсор, Tab, Enter и Backspace, строка пути, строка состояния, кнопки F-панели (пока без действий).
3. **Вкладки**: Ctrl+T, Ctrl+W, Ctrl+Tab и Ctrl+Shift+Tab.
4. **Выделение как в TC**: Insert, Space, Num+, Num−, Num*, Ctrl+A.
5. **Операции**: F5, F6, Shift+F6 и F2 (переименование), F7, F8 и Shift+F8, прогресс, конфликты.
6. **Завершение**: F3 и F4, кнопки дисков, watcher, конфиг. После этой вехи MVP готов.
