# 33. Поиск: регулярное выражение для имени, архивы, запоминание фильтров

Статус: решения приняты сами (пользователь: «давай по плану идём всё что можно сделать»). Из «Поиск, дальше».

## Решения

| Вопрос | Решение |
|---|---|
| Регулярное имя | Флажок «Имя — регулярное выражение»: поле маски — `regex::Regex` по имени (без учёта регистра, как маски; Unicode). Подпись поля меняется. Ошибка — в строке состояния диалога, поиск не начинается |
| Архивы | Флажок «Искать в архивах (по именам)»: файлы zip/tar.*/7z (`Format::is_tree`) — их записи сверяются с именем, размером и датой; найденное — путь через архив (`/x/a.zip/docs/f.txt`), Enter открывает этот каталог архива. Текст внутри архивов не ищется (с текстом поиска архивы не открываются). Индекс читается заново, мимо кеша одного архива (иначе поиск выбивал бы архив, открытый в панели). Каталоги, существующие только как родители записей, не находятся |
| «В панель» | Только файлы на диске: найденное в архивах туда не попадает (операции панели работают с настоящими путями) |
| Запоминание | Все поля и флажки (`FindPrefs`: + regex, name_regex, archives, размеры, дни) — в состоянии; старое состояние читается (`#[serde(default)]`) |
| «В панель» с клавиатуры | Нет: TC Alt+L, у нас Alt+буква — быстрый поиск, а перехватит ли его поле ввода, без ручной проверки не узнать. В бэклог |
| Вид | Четыре флажка в одном ряду: при 1036×530 иначе почти не остаётся места списку |

## Тесты

Core: регулярное имя вместо маски (кириллица без учёта регистра, ошибка разбора); архив — без флажка ничего, с флажком записи, фильтр размера по записям, скрытые, текст не открывает архивы.
App: плохое регулярное имя не запускает поиск; флажки и поля сохраняются и восстанавливаются после перезапуска.
