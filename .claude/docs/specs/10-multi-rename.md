# 10. Групповое переименование Ctrl+M

Статус: одобрен.
Основа: [архитектурный спек](00-architecture-design.md), [операции](05-file-ops.md), [эталон TC](../tc-reference.md).

## Решения

| Вопрос | Решение |
|---|---|
| Объём | Ядро TC: маски имени и расширения, счётчик, дата, найти/заменить, регистр, предпросмотр |
| Регулярные выражения | Нет (позже) |
| Отмена (undo) | Нет (позже) |
| Что переименовываем | `targets()` активной панели: файлы и папки, в порядке панели |
| Порядок применения | маска → найти/заменить → регистр |
| Проблемы | Подсвечиваются в предпросмотре; пока есть хоть одна, «Переименовать» и Enter не работают |
| Цепочки и обмен (a→b, b→a) | Работают: план упорядочивает пары, циклы разрываются временным именем |

## Маски

Позиции считаются в символах (`char`), а не в байтах. Расширение — всё после последней точки; у `.bashrc` и `Makefile` расширения нет.

| Маска | Подставляет |
|---|---|
| `[N]` | имя без расширения |
| `[N3]` | 3-й символ имени (с 1) |
| `[N2-5]` | символы со 2-го по 5-й |
| `[N2-]` | со 2-го до конца |
| `[E]`, `[E2]`, `[E1-2]`, `[E2-]` | то же для расширения |
| `[C]` | счётчик |
| `[Y]` `[M]` `[D]` `[h]` `[m]` `[s]` | дата и время изменения: `2026`, `10`, `02`, `14`, `05`, `09` (в поясе `tz`, через `jiff`, как `format::date`) |
| `[[`, `]]` | литералы `[` и `]` |

- Диапазон за пределами строки обрезается (`[N10-20]` у `abc` → пусто).
- Неизвестная или незакрытая маска (`[X]`, `[N`) остаётся как есть, текстом.
- Итог: `маска_имени` + (`.` + `маска_расширения`, если она дала непустое).

Счётчик: начало (по умолчанию 1), шаг (1), разрядность (1, т.е. без нулей). `[C]` у i-го файла = `start + i·step`, дополненное нулями до разрядности.

Найти/заменить: обычный текст, все вхождения, с учётом регистра; пустое «найти» — шаг пропускается. Применяется к полному новому имени (с расширением).

Регистр: как есть / ВСЕ ЗАГЛАВНЫЕ / все строчные / Первая заглавная (первая буква имени заглавная, остальные строчные). Применяется к полному имени.

## Ядро: `multirename.rs`

```rust
pub enum Case { Keep, Upper, Lower, Title }
pub struct Counter { pub start: i64, pub step: i64, pub digits: usize }
pub struct Rule { pub name: String, pub ext: String, pub find: String, pub replace: String,
                  pub case: Case, pub counter: Counter }
pub enum Problem { BadName, Duplicate, Exists }
pub struct Row { pub old: String, pub new: String, pub problem: Option<Problem> }

pub fn new_name(rule: &Rule, old: &str, mtime: SystemTime, index: usize, tz: &TimeZone) -> String;
/// `files`: (name, mtime) in panel order; `taken`: other names in the dir that are not renamed.
pub fn preview(rule: &Rule, files: &[(String, SystemTime)], taken: &HashSet<String>,
               tz: &TimeZone) -> Vec<Row>;
/// Ordered pairs; unchanged rows dropped; cycles go through a temp name. Rows must have no problem.
pub fn plan(dir: &Path, rows: &[Row]) -> Vec<(PathBuf, PathBuf)>;
```

Проблемы:
- `BadName`: пустое, `.`, `..` или содержит `/`;
- `Duplicate`: то же новое имя у двух и более строк (помечаются все);
- `Exists`: новое имя есть в `taken` (файл каталога, который не переименовывается).

Новое имя, совпадающее со старым именем другой переименовываемой строки, — не проблема: это цепочка или обмен.

`plan`: пара, чья цель — ещё не освобождённое старое имя, ждёт; если ждут все оставшиеся (цикл), одна из них идёт сначала во временное `.<имя>.<pid>.shagoff-mr` в том же каталоге, а в конце — в цель. Каждая пара — обычное переименование в том же каталоге.

## Приложение

- keymap: Ctrl + физическая `KeyM` → `Action::MultiRename`.
- `MultiRename`: нет целей или идёт операция — ничего. Иначе `Dialog::MultiRename` с копией целей (имя + mtime из `Entry`), набором `taken` (остальные имена текущего списка, включая скрытые, если показаны; при неудаче перечитать — то, что в панели) и полями правила.
- Диалог: поля маски имени (`[N]`), маски расширения (`[E]`), найти, заменить; выбор регистра; счётчик (начало, шаг, разрядность); ниже прокручиваемая таблица «Было → Станет», строки с проблемой выделены и подписаны. Предпросмотр пересчитывается при каждом изменении поля.
- Enter / «Переименовать» без проблем → `Job::Transfer { method: Move, pairs: plan(..) }` через существующий движок: прогресс, ошибки (повторить / пропустить / отмена), после — перечитать обе панели. Пустой план (ничего не меняется) — просто закрыть.
- Курсор после операции — на новом имени файла, который был под курсором (как у Shift+F6).
- Escape / «Отмена» — закрыть.
- Строки `en` и `ru`.

## Тесты

Core:
- каждая маска; диапазоны за краем; кириллица; без расширения, `.bashrc`, `a.tar.gz`; `[[`/`]]`; неизвестная маска;
- счётчик: начало, шаг, разрядность, отрицательный шаг;
- найти/заменить: несколько вхождений, пустое «найти»;
- регистр: все четыре режима, кириллица;
- проблемы: `BadName`, `Duplicate` (обе строки), `Exists`; цепочка не проблема;
- `plan`: неизменные строки выпадают; цепочка a→b, b→c упорядочена; обмен a↔b идёт через временное имя; на реальном tempdir выполнение пар даёт ожидаемые имена.

App: Ctrl+M открывает диалог с целями; правка поля меняет предпросмотр; Enter при проблеме ничего не запускает; Enter без проблем запускает перенос.

Вручную (TESTING.md): `[N]_[C]` на нескольких файлах, обмен двух имён, отмена посреди.

## Вне фичи

Регулярные выражения, отмена, пресеты масок, поля плагинов/метаданных, `[P]` (имя родительского каталога), редактирование списка имён во внешнем редакторе.
