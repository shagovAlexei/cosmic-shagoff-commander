# 69. Очередь операций — исправления

Техдолг ревью фазы 68 (`ROADMAP.md`, «Техдолг»). Патч 0.12.1.

1. **План при старте.** F5 / F6 считали пары `ops::plan` при постановке в очередь. Если операция
   впереди создала каталог-цель, файл шёл «поверх каталога» (конфликт). Теперь `Queued.replan`
   хранит источники и цель; `finish_job` пересчитывает пары перед стартом. Ошибка плана —
   в строку состояния, следующая из очереди. `side` — индекс панели, не меняется; курсор не
   хранится (только имя `focus`), снятие отметок по путям — безвредно в другом каталоге.
2. **Выход.** libcosmic закрывал окно до того, как приложение узнавало. Теперь
   `Settings::exit_on_close(false)`: × заголовка → `on_app_exit`, Alt+F4 / компоновщик →
   `window::close_requests()`, пункт меню «Выход» — все в `Message::Quit`. Нет операции и очереди →
   выход; иначе диалог «Идёт файловая операция» (Отмена / «Прервать и выйти»). Подтверждение
   отменяет операцию и очередь, выход — когда рабочий поток остановился и убрал `.shagoff-part`.
   Enter диалог не подтверждает (только кнопка).
3. **Вопрос поверх диалога.** Конфликт / ошибка фоновой операции при открытом диалоге ждут в
   `App.held` и показываются, когда диалог закрыт (`update`). Отмена операции бросает отложенный
   вопрос (ответ «Отмена»). Отложенный вопрос операции не заменяется вопросом о выходе.
