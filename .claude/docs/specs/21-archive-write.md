# 21. Запись в архив

Статус: решения приняты сами (пользователь: «запускай следующую фазу» — следующий пункт бэклога «Запись в архив: F5 в архив, F8 из архива, F4 с упаковкой обратно»).

## Решения

| Вопрос | Решение |
|---|---|
| Что можно | F5 в архив (другая панель в архиве или путь из диалога ведёт в архив), F6 в архив (копия, потом удаление источников, у которых всё скопировалось), F6 из архива наружу (извлечь, потом удалить извлечённое из архива), F8 / Shift+F8 / Delete внутри архива (всегда безвозвратно, как в TC), F7 — папка в архиве, Shift+F6 / F2 — переименовать, F4 — правка с упаковкой обратно |
| Что по-прежнему только для чтения | Ctrl+M, Ctrl+X / Ctrl+V, Alt+F5 / Alt+F9 внутри архива, вложенные архивы, синхронизация с архивом |
| Форматы | Все, что открываются как папки: zip, tar, tar.gz/bz2/xz/zst, 7z |
| Как меняется архив | Целиком заново: распаковать во временный каталог `.shagoff-unpack.<pid>.<n>` рядом с архивом, применить изменение на диске, упаковать в тот же формат во временный файл там же, переименовать поверх архива (права файла сохраняются). Исходный архив не трогается, пока новый не готов: отмена или ошибка на любом шаге оставляют его как был. Так переиспользуются проверенные распаковка и упаковка (конфликты, ошибки, отмена, прогресс) и все форматы работают одинаково. Цена: большой архив переписывается долго и требует места на диске; не сохраняются комментарий zip и настройки сжатия исходного архива |
| Если в архиве есть записи, которые нельзя распаковать (небезопасный путь, пропуск по ошибке) | Архив не меняется: иначе эти записи молча пропали бы |
| Конфликт при F5 в архив | Тот же диалог «Заменить?», что у F5 |
| F4 в архиве | Файл извлекается во временный каталог и открывается в редакторе. Раз в 2 секунды приложение проверяет время изменения таких файлов; изменился — диалог «Файл изменён в редакторе. Обновить архив?» (Да / Нет). Да — запись заменяется; Нет — больше не спрашивать об этом изменении. Временные файлы удаляются при выходе, как сейчас |
| Удаление из архива | Диалог подтверждения с текстом «безвозвратно», корзины нет |

## Ядро

Новый модуль `repack.rs`:

```rust
pub enum Change {
    Add { sources: Vec<PathBuf>, inner: PathBuf }, // F5 / F6 в архив
    Delete(Vec<PathBuf>),                          // F8, F6 из архива (пути внутри)
    Mkdir(PathBuf),                                // F7
    Rename { from: PathBuf, to: PathBuf },         // Shift+F6
    Replace { entry: PathBuf, file: PathBuf },     // F4
}
/// Rewrite `archive` with `change`. `completed`: Add — sources fully copied; Delete — `archive/entry`
/// of the deleted entries; others — `[archive]`. Nothing completed → the archive is unchanged.
pub fn modify(archive: &Path, change: &Change, h: &mut dyn Handler) -> Report;
```

## Приложение

- `read_only` разрешает перечисленное выше; F5/F6 с целью в архиве → `Job::Repack { archive, change }`; F6 из архива → `Job::ExtractMove` (извлечь, затем `Delete` для извлечённого без пропусков).
- F4 в архиве: `open_from_archive` с редактором; `App.edited: Vec<Edited { file, archive, entry, mtime }>`; подписка `time::every(2 s)` только пока список не пуст; изменение → `Dialog::Repack`.

## Тесты

Core: Add (в корень и в подкаталог, все форматы: zip, tar.gz, 7z), Delete (файл и каталог), Mkdir, Rename, Replace; цель уже есть при Rename / Mkdir → ошибка, архив не изменён; конфликт при Add спрашивает; отмена во время упаковки оставляет архив прежним и не оставляет временных файлов; права архива сохраняются; удаление всех записей даёт пустой архив.
App: F8 внутри архива открывает подтверждение «безвозвратно» и запускает `Repack`; F5 в панель с архивом — `Repack::Add`; Ctrl+M в архиве по-прежнему «только для чтения»; изменённый после F4 файл даёт диалог, «Нет» больше не спрашивает.
