# 32. Lister: перенос строк и кодировки

Статус: решения приняты сами (пользователь: «давай дальше по плану, проверю позже»). Из бэклога «Lister, дальше» — то, что проверяется тестами без ручного прогона.

## Решения

| Вопрос | Решение |
|---|---|
| Кодировки | Windows-1251, KOI8-R, DOS 866 и UTF-8 (+ UTF-16/UTF-8 по BOM, как было). Таблицы верхней половины (0x80–0xFF) — строки по 128 символов, сгенерированы из кодеков Python; без новой зависимости (`encoding_rs` нет в `Cargo.lock`) |
| Клавиши | TC: `A` — ANSI (1251), `S` — DOS (866); свои: `K` — KOI8-R, `8` — UTF-8. Физические клавиши, как остальные клавиши Lister. Выпадающий список в строке Lister |
| Поведение | Из hex переключает в текст (TC). Поиск — по перекодированному тексту. Hex всегда показывает байты файла. Кодировка и перенос сохраняются при N / P |
| `W` | Перенос по ширине окна: строка режется каждые N символов (N — ширина области / ширина символа), не по словам; ширина окна изменилась — переносится заново. Кнопка «Перенос (W)» |
| Автоопределение | Нет: без BOM — UTF-8. В бэклог |
| Где считается | `core::lister::Text::new(doc, encoding, wrap)` — перекодированные байты, индекс строк, ширина. В UI-потоке при переключении (32 МБ — заметная пауза; ponytail) |

## Тесты

Core: «Привет» в трёх кодировках, `Ёё№`, таблицы по 128 символов; `Text` — перенос по 3 символа, перекодировка, нулевая ширина не зацикливается.
App: кодировка из hex включает текст, перенос по ширине, пересчёт при изменении ширины, сохранение при `reopen`, сброс к `Loaded::text`; клавиши `W A S K 8` свободны в основной таблице.
