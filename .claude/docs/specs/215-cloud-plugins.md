# 215. Плагины облаков: OneDrive, Google Drive, Dropbox, Box

ROADMAP 215a (каркас: вкл / выкл), 215b (OneDrive), 215c (Google Drive, Dropbox, Box — тем же путём).

## Почему rclone, а не gvfs (проверено 2026-11-02 на Pop!_OS 24.04)

Сначала пробовали GOA + gvfs 1.54 (`gvfsd-google`, `gvfsd-onedrive` уже в системе):

- Google Drive подключился (`gio mount google-drive://…`), но в FUSE-каталоге `$XDG_RUNTIME_DIR/gvfs/google-drive:host=gmail.com,user=…` **имена — id объектов** (`0B0UpxLbFkOtJdks5ZVZLZzUzb3M` вместо `image-….jpg`, `1dkePel4…` вместо «Работа»); Google-документы и ярлыки — нечитаемые ссылки (`readlink`: Function not implemented). Настоящее имя есть только в `gio list -a standard::display-name`. F5 из облака по FUSE создавал бы файлы с именами-id.
- OneDrive в gvfs устроен так же (по образцу google) и на 24.04 у части личных аккаунтов обрывается («The connection is closed», LP #2064147; исправленный `libmsgraph-0-1 0.2.1-0ubuntu3.1` только в noble-proposed).

`rclone mount` показывает облако как FUSE-каталог **с настоящими именами**; один механизм на OneDrive, Google Drive, Dropbox, Box (и ещё десятки). В Ubuntu 24.04: `rclone 1.60.1` (universe), FUSE — `fusermount` → `fusermount3`, уже стоит. GOA больше не нужен.

## Что такое плагин

Строка таблицы `core::cloud::PLUGINS`: id, имя, тип хранилища rclone. Трейт не вводим (реализация одна — rclone); внешние плагины по IPC — с 208b.

| id | имя | тип rclone |
|---|---|---|
| `onedrive` | OneDrive | `onedrive` |
| `gdrive` | Google Drive | `drive` |
| `dropbox` | Dropbox | `dropbox` |
| `box` | Box | `box` |

Учётная запись = «remote» rclone в `~/.config/rclone/rclone.conf` (rclone сам создаёт его 0600). Свои remote пользователя этих типов тоже видны — это плюс.

## Поведение

### Ctrl+, → «Облака»

Новый раздел настроек.

- Нет `rclone` в `PATH` — одна строка: «Для облаков нужен rclone: `sudo apt install rclone`» (выделяемый текст). Больше в разделе ничего.
- Иначе по блоку на плагин: переключатель «OneDrive» (вкл / выкл), под ним его учётные записи (имя remote + «Удалить»), кнопка «Добавить учётную запись».
- «Добавить учётную запись»: `rclone config create <имя> <тип>` в фоне; rclone сам открывает браузер (вход и разрешение у Microsoft / Google / …), ждёт ответа на `127.0.0.1:53682`. В строке состояния «Вход в браузере… Esc — отмена»; Esc убивает процесс (группу). Имя — id плагина, занятое → `onedrive-2`, `onedrive-3`. Успех — учётная запись в списке и том в Alt+F1; ошибка — текст rclone в строке состояния.
- «Удалить»: если подключено — отключить; затем `rclone config delete <имя>` (только токен у нас; файлы в облаке не трогаются). Без подтверждения: войти снова — одна кнопка.
- По умолчанию все плагины включены: без учётной записи их не видно.

### Облако как диск

- Учётная запись включённого плагина — неподключённый том в Alt+F1 / Alt+F2 и в кнопках дисков, как флешка «(не подключён)» (фаза 41): `OneDrive (не подключён)`; если имя remote не совпадает с id плагина — `OneDrive: work (не подключён)`.
- Enter / щелчок — `rclone mount <имя>: <точка> --daemon --vfs-cache-mode writes`; переход в точку. `writes` нужен для наших `.shagoff-part` + `rename` и для F4.
- Точка монтирования: `$XDG_RUNTIME_DIR/shagoff-clouds/<id плагина>:<имя remote>` (каталоги 0700). Имя каталога несёт плагин, поэтому кнопка диска и фильтр по выключенным плагинам берутся из `/proc/self/mounts` без лишних вызовов rclone.
- Подключённое облако — кнопка диска (`fuse.rclone` под этим корнем) с той же подписью без «(не подключён)». Ctrl+Shift+F — `fusermount -u <точка>`, каталог удаляется.
- F5 / F6 / F7 / F8, F3 / F4 — как с любым каталогом. Корзины нет: F8 удаляет навсегда, как на сетевых дисках.
- Подключённое остаётся после выхода из программы (как gvfs); после перезагрузки — снова Enter.

### Выключенный плагин

Его тома и кнопки дисков не видны нигде, учётные записи в настройках свёрнуты (виден только переключатель). Уже подключённое не отключаем — панель, открытая в нём, остаётся.

## Риски

1. ~~`rclone config create` для OneDrive может спросить тип / диск~~ — проверено 2026-11-02: сам выбрал `drive_type = personal` и диск, вопросов нет. Google Drive и OneDrive смонтированы с настоящими именами; запись `.part` → `rename`, `touch -d`, `rm -r` в облаке работают. Вход в браузере может длиться минуты (Google — 10 мин): своего тайм-аута нет, только Esc. remote пишется в конфиг до входа — прерванный вход оставляет пустую учётку, `add` её удаляет.
2. Google Drive через общий client id rclone ограничен по частоте запросов (большие каталоги — медленно). Свой client id — настройка позже, если попросят.
3. Токены в `rclone.conf` открытым текстом (0600, как у rclone всегда). Шифрование конфига rclone требует пароль на каждое подключение — не делаем.
4. Пропал интернет при подключённом облаке: FUSE-вызовы rclone ждут; наш `scan` идёт в фоне, окно не зависает (как с sftp).

## Что меняется

- `core::cloud` (новый): таблица, разбор `rclone listremotes --long`, разбор `/proc/self/mounts`, имена, команды rclone / fusermount.
- `core::mount`: `list()` добавляет облачные тома (`device` = `rclone:<имя>`), `mount_device("rclone:…")` → `cloud::mount`, `unmount` для точки под корнем облаков → `cloud::unmount`, `removable` — и облака.
- `Config.plugins_off: Vec<String>` (выключенные id, `Default` пусто).
- app: фильтр томов и дисков, кнопки дисков облаков, раздел «Облака», добавить / удалить / отмена.
- tc-reference.md: строка «Облака» (в TC — плагины файловой системы `.wfx` в «Сетевом окружении»).

## Не делаем

- gvfs / GOA для облаков (см. выше).
- Свой OAuth, Microsoft Graph, синхронизация, офлайн-копии.
- Свой client id, шифрованный `rclone.conf`, остальные типы rclone (S3, WebDAV… — WebDAV уже есть в Ctrl+F) — по запросу.
- Внешние плагины по IPC — 208b.
