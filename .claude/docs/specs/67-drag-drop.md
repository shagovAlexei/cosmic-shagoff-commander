# 67. Drag & drop

Как в TC (перетаскивание левой кнопкой):

- **Откуда тянем.** Строка панели: если она отмечена — тянутся все отмеченные, иначе только она;
  `..` не тянется. Из архива в другую панель — как F5 (распаковка); в другие программы из архива
  не выйдет (файлов на диске нет).
- **Куда бросаем.**
  - На строку-каталог (и на `..`) — в этот каталог; строка подсвечивается, пока над ней тянут.
  - На свободное место / файл панели — в каталог панели.
  - Бросить в тот же каталог, откуда взяли, или каталог сам в себя — ничего не происходит.
  - В панель с результатами поиска / ветвью — нельзя (каталог неоднозначен).
- **Что происходит.** Как F5 / F6 в TC (с подтверждением): открывается тот же диалог копирования,
  путь — каталог броска. Копирование по умолчанию, **Shift** — перенос (действие выбирает
  композитор по модификаторам, приходит `DndAction`). В архив / из архива — как F5 / F6.
- **Другие программы.** Тянем наружу — `text/uri-list` + `x-special/gnome-copied-files` (как
  Ctrl+C), принимает Files, рабочий стол, браузер. Бросаем к нам из Files — тот же диалог.

Где: `Panel::drop_dir` / `panel::drop_is_noop` (ядро; что тянется — в `view::dnd_row`);
`clip.rs` — `dnd_source` / `dnd_destination` libcosmic; `Message::Drop`, `Message::DropHover`.

Устройство: `context_menu` и `sensor` libcosmic не пропускают зоны приёма внутрь
(`drag_destinations`), поэтому меню и датчик размера — нижний слой `stack` под списком, а не
обёртка вокруг него. Источник — окно (`.window(id)`): id виджета новый каждый кадр. Пока тянут
границу колонки, строки не источники (источник перехватывает движение мыши).

Не делаем: картинку под указателем (`drag_icon` роняет libcosmic «Downcast on stateless state»),
правую кнопку (меню «Копировать / Переместить / Ссылка»), бросок на кнопки дисков и
вкладки, ссылку (Ctrl+Shift), без подтверждения.
