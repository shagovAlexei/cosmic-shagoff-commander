## `listing.rs`

```rust
pub enum Kind { Dir, File }
pub struct Entry { name: String, os_name: OsString, ext: String, size: u64, mtime: SystemTime, kind: Kind, is_link: bool }
pub fn scan(path: &Path, show_hidden: bool) -> io::Result<Vec<Entry>>
```

- Ошибку чтения самого каталога возвращаем вызывающему. Если не удалось прочитать отдельный элемент, пропускаем его.
- Симлинк на каталог: `Kind::Dir`, `is_link = true`. Битый симлинк: `Kind::File`, `is_link = true`, размер 0.
- `ext` бывает только у файлов: это часть имени после последней точки, если точка не первый символ (`archive.tar.gz` → `gz`, `.bashrc` → пусто). У каталогов расширения нет.
- Скрытый элемент — тот, чьё имя начинается с `.`. При `show_hidden = false` такие пропускаем.
- `name` — имя для показа (`to_string_lossy`), `os_name` — настоящее имя на диске. Пути строятся только из `os_name`, поэтому в каталог с именем не в UTF-8 можно войти. Если два имени после замены символов совпали, порядок решает `os_name`.
- `..` здесь не добавляем.

## `sort.rs`

```rust
pub enum SortKey { Name, Ext, Size, Date }
pub struct Sort { key: SortKey, asc: bool }  // Default: Name, asc
pub fn natural_cmp(a: &str, b: &str) -> Ordering
pub fn sort_entries(entries: &mut [Entry], sort: Sort)
```

- Каталоги всегда стоят выше файлов, в любом направлении.
- При `SortKey::Size` каталоги сортируются по имени.
- Если ключи равны, порядок решает `natural_cmp` по имени.
- Направление `asc = false` разворачивает порядок внутри групп, но каталоги остаются сверху.
- `natural_cmp` без учёта регистра. Подряд идущие цифры сравниваются как числа: `file2 < file10`. При полном равенстве без учёта регистра порядок решает обычное сравнение строк, чтобы сортировка была детерминированной.

## `panel.rs`

```rust
pub struct Panel { cwd: PathBuf, entries: Vec<Entry>, cursor: usize, sort: Sort, show_hidden: bool }
```

- `Panel::new(cwd)` создаёт панель с пустым списком. Каталог потом читает UI.
- `set_listing(cwd, entries, focus: Option<&str>)` — единственный способ загрузить каталог, поэтому панель не может оказаться в промежуточном состоянии «новый каталог, старый курсор»:
  - сортирует;
  - вставляет первой строкой `..` (`Kind::Dir`), если у `cwd` есть родитель;
  - ставит курсор:
    - на `focus`, если такое имя есть;
    - иначе, если каталог тот же (перечитывание), — на имя под курсором, а если его уже нет, на прежний индекс;
    - иначе (новый каталог) — на первую строку;
    - в любом случае не дальше конца списка.
- `move_cursor(delta: isize)` двигает курсор с упором в края. Ещё есть `cursor_home()` и `cursor_end()`.
- `set_sort(key)`: та же колонка меняет `asc` на противоположное, новая колонка ставит `asc = true`. Список пересортировывается, курсор остаётся на том же имени, `..` остаётся первой.
- `current() -> Option<&Entry>`.
- `parent_path() -> Option<(PathBuf, String)>` возвращает новый путь и имя для фокуса.
- `enter_path() -> Option<(PathBuf, Option<String>)>` возвращает путь и фокус: для `..` — как `parent_path`, для каталога — вложенный путь без фокуса, для файла — `None`.

Panel сама файловую систему не читает. UI вызывает `scan` в `spawn_blocking`, и только если он прошёл успешно, вызывает `set_listing`. Поэтому при ошибке панель остаётся в прежнем каталоге.

## Тесты

- `natural_cmp`: числа, регистр, префиксы, пустые строки.
- `sort_entries`: каталоги сверху по каждому ключу и направлению, каталоги по имени при `Size`, равные ключи упорядочены по имени.
- `scan` во временном каталоге (`tempfile`): скрытые файлы, `ext`, симлинк на каталог, битый симлинк, ошибка на несуществующем пути.
- `Panel`:
  - `..` есть везде, кроме `/`;
  - курсор упирается в края;
  - курсор сохраняется на имени после `set_sort` и после повторного `set_listing` того же каталога;
  - в новом каталоге курсор встаёт на первую строку;
  - пустой каталог не ломает курсор;
  - если имя пропало, курсор встаёт на прежний индекс;
  - `focus` после выхода вверх;
  - `enter_path` и `parent_path`.
