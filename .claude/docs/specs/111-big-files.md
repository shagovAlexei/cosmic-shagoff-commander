# 111 — Просмотр файлов больше 32 МБ

Lister держит в памяти «окно» — до 32 МБ файла — и сдвигает его по файлу, как TC читает большой файл по частям.

- Текст: окно начинается с начала строки (после `\n`; в UTF-16 — после `\n` из двух байтов на чётном смещении, следующие окна декодируются тем же BOM). Hex: окно с кратного 16 смещения, адреса в строках — от начала файла.
- Прокрутка к нижнему краю окна, а файл продолжается, — окно сдвигается на половину вперёд; к верхнему краю, а окно не с начала файла, — на половину назад. Видимая строка остаётся на месте: сдвиг прокрутки — число строк окна до начала нового (по `\n`, с учётом переноса и кодировки).
- Home — окно с начала файла, End — окно, кончающееся концом файла (низ).
- Поиск F7 / F3 / Shift+F3: не найдено в окне — следующее (предыдущее) окно без перекрытия, пока не найдено или файл не кончился; в строке состояния «Ищу … дальше по файлу…». Не найдено — обратно в то окно и на то место, откуда начали (как в TC). Совпадение в последней (обрезанной) строке окна при F3 дальше не находится второй раз; в hex окна поиска перекрываются на длину запроса. Home / End во время поиска его прерывают (ответ старого чтения отбрасывается).
- Вместо «Показаны первые 32 МБ из …» — «Показано 32–64 МБ из 10 ГБ».
- Выделение и подсветка найденного при сдвиге снимаются.
- Картинки больше 32 МБ — как раньше (не окно). Режим, кодировка, перенос сохраняются между окнами; угадывается кодировка только по первому окну.

Не делаем: полосу прокрутки на весь файл (в окне — своя), отмену длинного поиска (кроме закрытия просмотра, Home / End); окно, прочитанное в тексте, при переключении в hex остаётся (адреса не кратны 16) до следующего сдвига.
